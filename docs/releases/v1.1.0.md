# v1.1.0

Parse tree nodes know where they came from in the input. A rule handler that builds an AST can now record each node's position, report errors at the right place, or map its result back to the source. Before this, a terminal node kept only its token's value, and the token's position was dropped when the node was made.

## Added

- Each terminal node keeps the token it was shifted from, as `node.token` (PR 18). The LR, LL and GLR parsers all set it. It is null for a non-terminal and for a node a caller builds by hand.
- Every node has `start` and `end`. A terminal takes its token's. A non-terminal spans its first to its last child that covers any input, so a child that a `beforeAddingChildNode` callback dropped doesn't count. Both are computed when read, so they follow the children a node actually has.
- `end` is exclusive, like tlex's `Token.end`, so a node's text is `input.substring(node.start, node.end)`. Both are null for a node that covers no input, such as an empty reduction.

```ts
const [parser] = newParser(grammar);
const tree = parser.parse("[1, 22]");
// The NUMBER node for 22 has start 4 and end 6.
```

## Known gaps

- The GLR parser sets `token` too, but has no test for it, because `glr.Parser.parseInput` returns an empty forest (issue 11).
- Positions are character offsets. Line and column are left to the caller, or to tlex.

## Upgrading

No code changes needed. The additions are new members on `PFNode`, and nothing existing changed.
